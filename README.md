## Бизнес-контекст и постановка задачи

**Контекст:** Исследование проводится для e-commerce стартапа — нового маркетплейса экзотических товаров из Бразилии. На текущем этапе продукт демонстрирует стагнацию ключевых финансовых показателей: общая выручка компании не растет на протяжении нескольких месяцев. 

**Главная цель проекта:** Комплексный аудит продуктовых метрик, выявление узких мест в воронке продаж, проверка продукта на соответствие рынку (Product/Market Fit) и формирование аналитически обоснованного пула гипотез для возобновления кратного роста без ухудшения пользовательского опыта (Customer Experience).

---

## Перечень аналитических задач

В ходе реализации проекта были последовательно решены следующие задачи:

1. **Когортный анализ удержания:** Оценка ежемесячного показателя Retention Rate пользователей на этапе оформления заказа для выявления паттернов возвращаемости клиентов.
2. **Анализ соответствия рынку (Product/Market Fit):** Проверка устойчивости бизнес-модели стартапа (анализ выхода кривой Retention на стабильное «плато»).
3. **Разработка системы метрик:** Определение ТОП-5 ключевых продуктовых и бизнес-метрик, на которых необходимо сфокусировать внимание менеджмента для максимизации чистой прибыли компании.
4. **Приоритезация продуктовых гипотез:** Скоринг и ранжирование трех основных векторов развития продукта с использованием методологии **ICE (Impact, Confidence, Ease)**.
5. **Дизайн экспериментов (A/B-тестирование):** Формирование сбалансированной системы метрик (Target, Proxy, Guardrail) для оценки эффективности приоритетной гипотезы в ходе грядущего сплит-теста.
6. **Бизнес-отчетность:** Формализация инсайтов, подведение итогов исследования и формирование финального пакета рекомендаций для продуктовой команды.

## Структура данных (Датасет Olist)

В анализе используются три реляционные таблицы с историческими логами транзакций маркетплейса:

* `olist_customers_dataset.csv` — данные о клиентах:
  * `customer_id` — позаказный идентификатор пользователя.
  * `customer_unique_id` — уникальный сквозной ID пользователя (аналог ID паспорта).
  * `customer_city` / `customer_state` — география доставки (город / штат).

* `olist_orders_dataset.csv` — логи жизненного цикла заказов:
  * `order_id` — уникальный идентификатор транзакции (номер чека).
  * `order_status` — текущий статус обработки (`created`, `approved`, `processing`, `shipped`, `delivered`, `unavailable`, `canceled`).
  * `order_purchase_timestamp` — дата и время создания заказа.
  * `order_delivered_customer_date` — фактическое время вручения посылки клиенту.
  * `order_estimated_delivery_date` — плановая (обещанная) дата доставки.

* `olist_order_items_dataset.csv` — товарные позиции внутри чеков:
  * `product_id` — уникальный идентификатор товара.
  * `seller_id` — идентификатор производителя/продавца.
  * `price` — стоимость единицы товара.
  * `freight_value` — логистические параметры (вес / стоимость доставки).
